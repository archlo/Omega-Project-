# IDA-verified gaps: OG opcode handlers missing from TS

## Current status

Resolved in TS. The opcode constants, router registrations, typed packet args,
and generic decoded handlers for every concrete opcode listed below now exist in
`src/net/packet/OpCodes.ts`, `src/net/handlers/FieldHandlers.ts`, and
`src/net/handlers/PacketArgs.ts`. Regression coverage lives in
`tests/net/packet/OpCodes.spec.ts` and `tests/net/handlers/IdaNewGaps.spec.ts`.

Remaining work is feature/UI depth only, not missing wire coverage: several
handlers intentionally expose decoded generic fields because the full OG UI or
effect subsystem is not ported.

Follow-up implemented after this file was resolved: decoded/local mob damage
number placement now uses `MobLook.HeadPosition`, derived from the current WZ
frame's top/center instead of the old universal `mob.Position.y - 60` fallback
(`TODO_AUDIT.md` Hundred-and-fifty-sixth pass).

Follow-up social UI correction: the decoded GuildBBS and PartyAdver/PartySearch
consumers are covered by `GuildBBS`/`PartySearchDialog`; PartySearch UI coverage
was added in `tests/ui/game/PartySearchDialog.spec.ts` (`TODO_AUDIT.md`
Hundred-and-fifty-seventh pass).

Follow-up stale architecture correction: `CBattleRecordMan` is no longer wire
decoder only. `BattleRecord.ts` implements the tested damage aggregation/DPS
path and `BattleRecordHandlers.ts` feeds server calc/DoT updates; remaining
damage-board polish is separate medium/large UI work (`TODO_AUDIT.md`
Hundred-and-fifty-eighth pass).

Follow-up combo-finisher correction: `CSequencedKeyMan` is no longer zero
presence. The verified Double/Triple Stab subset is wired into local attack-key
gameplay; the full per-job restore table/specialized finishers remain open
(`TODO_AUDIT.md` Hundred-and-seventy-sixth pass).

Follow-up item-effect correction: `CItemEffectManager` has a narrow decoded
consumer now. Remote `UserSetActiveEffectItem` loops the resolved
`ItemEff.img/<itemId>/0` caster effect until cleared; full `CParticleEffect`
emitter/category behavior remains open (`TODO_AUDIT.md`
Hundred-and-seventy-seventh pass).

Follow-up medal-quest correction: `CUIMedalQuestInfo` now has a portable
subset. `/medals` opens WZ `QuestInfo.img` entries marked by `medalCategory`
or `viewMedalItem` through the existing quest-log/detail UI; the full OG
medal-specific layout/state polish remains open (`TODO_AUDIT.md`
Hundred-and-eightieth pass).

Follow-up event-alarm correction: `CUIEventAlarm` is no longer zero presence.
`SetField` decodes `nNotifierCheck` title/content strings and `EventAlarm.ts`
shows the timed popup (`TODO_AUDIT.md` Hundred-and-sixty-eighth pass). The
old StringPool-blocked note was stale.

Follow-up animation/particle correction: `CAnimationDisplayer` is no longer
"not IDA-investigated." `Effect_Tremble` is already covered by
`GameCamera.Shake()`/FieldEffect subtype 1, projectile fade covers the small
`FADEINFO` slice, and `CParticleEffect` was confirmed as a follow-animation
particle system with deeper emitter behavior still open (`TODO_AUDIT.md`
Hundred-and-eighty-first pass).

Follow-up CashShop/medal/NPC correction: CashItemResult's known sub-actions
now have readable CashShopStage status messages; medal quests show
`viewMedalItem` IDs; and the two real NPC `speak` label sets resolve through
`String/Npc.img` per `CNpcTemplate::GetChatMessageList` (`TODO_AUDIT.md`
Hundred-and-eighty-second pass).

Follow-up ponytail slice: `TownPortalNotify` status is replayed after SetField
HUD rebuilds, expedition invite/apply packets have native confirm consumers, and
`MobCatchEffect` attempts the existing `Effect/Catch.img` one-shot. A proposed
ContiMove status path was deliberately not added because local opcode evidence
maps 359-362 to boss timers, not ContiMove (`TODO_AUDIT.md`
Hundred-and-eighty-third pass).

Generated by decompiling the v95 OG client dispatch tables against
`src/net/packet/OpCodes.ts` and `src/net/handlers/FieldHandlers.ts`.

Covers the five main dispatch sites:
- `CWvsContext::OnPacket` (0x9E5830, 1401 bytes)
- `CField::OnPacket` (0x546D50, 1224 bytes) → route-through pools
- `CUserPool::OnPacket` (0x94DDF0) → `OnUserCommonPacket` (0x94CDB0) + `OnUserRemotePacket` (0x94B390)
- `CMobPool::OnPacket` (0x658E00) → `OnMobPacket` (0x6570B0)
- `CNpcPool::OnPacket` (0x679770)
- `CSummonedPool::OnPacket` (0x75AC70)
- `CReactorPool::OnPacket` (0x6CF9B0)
- `CCashShop::OnPacket` (0x4997E0)

## 1. CWvsContext — 16 pure opcode gaps

These opcodes have real handlers in the OG `CWvsContext::OnPacket` switch
but zero presence in the TS `OutHeader` enum. None are mentioned in
`STATUS.md`'s Known Gaps section.

| Opcode | OG handler method | Purpose | Priority |
|--------|-------------------|---------|----------|
| 37 | `OnGivePopularityResult` | Fame give attempt result | Low (fame is cosmetic) |
| 40 | `OnMemoResult` | Memo/note delivery result | Medium (social feature) |
| 41 | `OnMapTransferResult` | Map teleport scroll result | Low (teleport works without it) |
| 72 | `OnIncubatorResult` | Miracle cube incubator result | Medium (MIracleCube.ts exists) |
| 73 | `OnShopScannerResult` | Shop scanner search result | Low (CUIShopScanner not ported) |
| 82 | `OnBridleMobCatchFail` | Bridle (Monster Rider) capture fail | Low (pet system, not the riding) |
| 83 | `OnImitatedNPCResult` | NPC imitation result | Low (NPC wardrobe gimmick) |
| 115 | `OnSetAvatarMegaphone` | Avatar megaphone set/refresh | Low (megaphone text works) |
| 117 | `OnCancelNameChangeResult` | Name change cancel result | Low (char creation name check) |
| 118 | `OnCancelTransferWorldResult` | World transfer cancel result | Low (rare action) |
| 120 | `OnFakeGMNotice` | Fake GM notice broadcast | Low (admin/staff feature) |
| 122 | `OnNewYearCardRes` | New Year card result | Low (seasonal event) |
| 123 | `OnRandomMorphRes` | Random morph coupon result | Low (morphs work via buffs) |
| 129 | `OnCakePieEventResult` | Cake/Pie event response | Low (event-specific) |
| 135 | `OnStageChange` | Stage/field-state change | Medium (field transition) |

**Verdict:** All 16 are low-to-medium priority. None block core gameplay,
but they represent missing wire coverage that, if the server ever sends
one of these, the TS client silently ignores it (no handler registered).

## 2. CUserPool — 33 opcode gaps in the 179–241 range

### 2a. OnUserCommonPacket (opcodes 181–208) — 15 missing handlers

These opcodes route through `CUserPool::OnUserCommonPacket` (0x94CDB0)
which reads a `Decode4` charId, then dispatches.

| Opcode | OG handler | Notes |
|--------|------------|-------|
| 182 | `CUser::OnChat` (scrollback=1) | Same as 181 but sets history flag; TS only decodes 181 |
| 183 | `CUser::OnADBoard` | Player advertisement board |
| 185 | `CUser::SetConsumeItemEffect` | Consume-item glow/effect on char |
| 186 | `CUser::ShowItemUpgradeEffect` | Scroll success/fail sparkle on item |
| 187 | `CUser::ShowItemHyperUpgradeEffect` | Hyper upgrade effect |
| 188 | `CUser::ShowItemOptionUpgradeEffect` | Bonus potential effect |
| 189 | `CUser::ShowItemReleaseEffect` | Release/clean slating effect |
| 190 | `CUser::ShowItemUnreleaseEffect` | Unrelease effect |
| 191 | `CUser::OnHitByUser` | Player bumped by another player |
| 192 | `CUser::OnTeslaTriangle` | Tesla (priest/FP) triangle effect |
| 193 | `CUser::OnFollowCharacter` | Follow-me / guide follow |
| 194 | `CUser::OnShowPQReward` | Party quest reward popup |
| 195 | `CUser::OnSetPhase` | Phase change notification |
| 197 | `CUser::ShowRecoverUpgradeCountEffect` | Recover upgrade count (hammer) |
| 198–205 | Pet packet range | See below |

**Pet opcodes (198–205):** `CUser::OnPetPacket` (0x8E02A0)
- 198: `OnPetActivated` + `PetInterActWithUserAction` (pet summon/remove)
- 199: `OnPetEvol` (pet evolve from egg)
- 200: `OnPetActivated` (same as 198, no inter-act)
- 201: `CPet::OnMove` (pet movement)
- 202: `CPet::OnAction` (pet action/emotion)
- 203: `CPet::OnNameChanged` (pet rename)
- 204: `CPet::OnLoadExceptionList` (auto-loot/consume exception list)
- 205: `CPet::OnActionCommand` (pet action command)

**Dragon opcodes (206–208):** `CUser::OnDragonPacket` (0x8E5C00)
- 206: `CDragon::OnCreated` (dragon summon/remove — Evan class mount)
- 207: `CDragon::OnMove` (dragon movement)
- 208: no-op in OG (else branch with no handler)

## 6. Methodology

table extracted. The OG client binary is `Maplestory95.exe.i64` at the
repo root. All address references match the IDA database.
