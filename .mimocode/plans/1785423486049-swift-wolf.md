# Full 1:1 v95 Client Implementation Plan

## Hard Rules
1. **ALL WZ loading uses `.nx` files, NEVER `.wz`** — `wz_client/` has both; `.nx` is the already-decrypted/converted format this client's own `WzPackage.OpenBase` prefers.
2. **ALL UI coordinates, sizes, button IDs, and rendering logic come from IDA decompilations** — every pixel position must cite the OG function address. No guessing.
3. **WZ paths come from decompiled `IWzResMan::GetObjectA` / `PcCreateObject` calls** — trace the `bstr`/`Ztl_bstr_t` argument. If it's `StringPool::GetBSTR(id)`, resolve the ID.
4. **Run `tsc --noEmit` after every src/ edit. Run `vitest` when src/ or tests/ changed.**
5. **Ship verified-portable subset; document what's deliberately skipped.**
6. **Every fix gets an inline comment citing TODO_AUDIT.md pass.**

## Per-Feature Workflow
1. **Search** `function_list.txt` for OG class → get addresses
2. **Search** `decompiled.c` for `func-address: 0xNNNNNN` → get decompiled body
3. **Extract** coordinates, sizes, WZ paths, button IDs from decompile
4. **Verify** WZ assets exist in `wz_client/*.nx` at the exact paths
5. **Implement** in `src/` following existing patterns (GamePanel base, handler callbacks)
6. **Wire** in GameStage.ts + GameSender.ts + FieldHandlers.ts as needed
7. **Test** with spec file — verify decode/encode/render logic
8. **Document** in TODO_AUDIT.md + STATUS.md
